# 证据阅读指南

[返回评测首页](../README.md) · [附件总索引](README.md)

本指南只帮助阅读现有材料，不新增评分、改变严重度或替参赛方改写观点。

## 核查一项结论的顺序

1. 在[评分明细](%E8%AF%84%E5%AE%A1%E7%BB%93%E6%9E%9C_20260925_v1/%E8%AF%84%E5%88%86%E6%98%8E%E7%BB%86_%E6%9C%BA%E4%BC%9A%E7%9F%A9%E9%98%B5%E4%B8%8E%E4%BA%8B%E5%AE%9E%E8%A3%81%E5%86%B3.md)找到条目：G编号是发现机会，E编号加F编号是某份报告的事实族裁决。D3—D6为有理由说明的人工锚点评分。
2. 沿条目中的原文编号与行号回到参赛报告；必要时用[原文抽取](%E8%AF%84%E5%AE%A1%E7%BB%93%E6%9E%9C_20260925_v1/evidence/claims/claims.json)定位。先确认评审有没有准确表达作者的限定。
3. 打开独立核验底稿，检查目标/父提交、平台、触发时序、替身位置及影响。一个模拟探针成立，不自动代表生产频率或所有路径成立。
4. 对照源码和日志，再判断事实信用或严重度。文件存在证明可复核材料当前可取得，不自动认证报告全部历史过程。

## 分数能回答什么

这是单一提交、单份最终产物的评分。六维权重、机会集和事实裁决可复算，但人工判断仍可能受新证据修正。接近分数不应读成统计显著差异；729组权重计算不是729次独立实验，也不是产品胜率。

先读最终主报告与明细。反方复核文件中有旧草案分数，保留它们是为了公开修订过程，不能与最终表混用。后补用量数据缺少完整运行对应关系，未据此形成速度或性价比排名。

## 原件冻结与阅读便利如何兼顾

43份冻结Markdown保持原字节，不直接修复其中历史绝对路径。本包用新增导航提供可打开的附件位置。顶层报告可直接阅读；底层材料集中归档，不因为默认不展示就丢弃证据。

原件SHA表示冻结输入，发布SHA表示脱敏副本；两者可能不同。日志脱敏、重复日志统一和目录移动都有记录。后续加入的两组CSV展开副本已补齐user_id/api_key脱敏，不改变数字、模型、时间或API key名称。4个消失的原始过程路径继续标明缺失，独立复验不冒充原实验。

## 自己复算与检查

在资料包根目录执行，建议先复制资料包到临时目录：

```sh
# 只重算分数，会写入该临时副本的scores_computed.json
python3 证据附件/评审结果_20260925_v1/recompute_scores.py

# 校验冻结文件、导航、评分与数据，只更新校验结果JSON
python3 证据附件/校验与来源/validate_publication.py

# 需要复跑Java/Python实验时，先检查和恢复固定提交源码
python3 证据附件/校验与来源/restore_sources.py --repository /path/to/zhikuncode --dry-run
python3 证据附件/校验与来源/restore_sources.py --repository /path/to/zhikuncode
```

恢复脚本需要本地仓库拥有指定目标和父提交，不联网、不运行构建、不覆盖已有证据。历史镜像移除清单中的路径相对本包“证据附件”目录解释。新实验输出与旧日志分开保存，不把复跑结果回填成当时输出。历史render/build/finish脚本不是新版导航生成入口，不应直接运行来改写冻结文档。

## 如果要质疑或纠正

提供报告编号与原文行号、具体裁决ID、源码版本和可达条件，或可复现反例。若争议属于权重偏好，应对全部八份统一重算；若是事实错误，应先纠正事实再计算。这样才能区分“不同偏好导致换位”和“原裁决确实有误”。

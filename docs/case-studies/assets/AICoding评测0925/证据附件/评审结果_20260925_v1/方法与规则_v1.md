# 评分方法 v1（在出分前冻结）

本轮评价对象是冻结的八份最终 Markdown 报告（E08按用户后续指示在出分前加入）在这一项代码审查任务上的质量。不是模型能力总榜，也不能独立估算工具自身的因果贡献。用户告知模型和推理等级一致，缺少运行轨迹、token/成本、起止时间、上下文、并发负载、权限、配置、重试次数和中间稿，均记不可评价，不补造数据。缺少证据不等于造假。

## 证据与独立性

1. 输入逐文件快照+SHA-256；所有评审产物放独立子目录，不改参赛报告或被审源码。
2. Java和Python独立核验员先读提交而不读参赛报告；报告提取员单独抽取主张。主审已见报告名称，不宣称双盲；多代理使用同类模型且共享主审，不视作独立人类专家投票。
3. 真值由目标提交/父提交/调用链/确定性探针与聚焦回归测试裁决，不能由多数报告投票形成。
4. 相同根因合并计分；设计取舍、既有缺陷、运行条件、修复不完整和新回归分栏。不把“更严格”天然当错误，也不把“测试全绿”当无缺陷证明。
5. 每个重要主张记录支持、部分支持、反证、不足判定；严重度统一按实际影响与可达条件归一。不把 Linux/macOS 或模拟探针结果外推到所有生产环境。

## 六维评分（总分100）

- D1 有效发现与关键风险覆盖：30。先形成经核验的去重问题/契约机会集并公开权重，再按每项完整发现1、仅发现机制或漏关键条件0.5、遗漏0计算。任何仅个别报告提出的新真问题都进入统一机会集并回溯所有选手。不声称机会集涵盖所有潜在缺陷。
- D2 事实准确性：20。对重要、去重主张逐项裁决，按原报告严重度权重（高/P1=3、中/P2=2、低/P3=1），支持1、部分支持0.5、反证0；未能独立判定者列出并不当假阳性。明确已经撤回的初判不作为当前误报。正文和摘要冲突仍需扣分。所有分母公开。
- D3 因果归属与风险校准：15。三项各5：父提交归因、平台/可达/触发边界、严重度及发布结论相称。每项0至5，逐条写理由；存在定级体系差异先按定义解读，不能机械对齐P编号。
- D4 证据与验证质量：15。三项各5：可检查的静态证据/调用链、测试与探针的可复核性、反证/父提交对照/局限披露。坦承未实跑不按造假扣分，但不能获得动态验证分。测试数量不是得分代理；未附可定位输出的自述不能获得与实物证据同等分数。
- D5 任务范围与工程审查：12。功能链路、代码质量、测试质量/CI、规范性各3；有论据的具体分析得分，模板式泛述仅部分得分。不把源码未变当作传递影响绝对不存在的证据。
- D6 可行动性与交付：8。建议安全且对症4、定位/优先级/阅读与复现便利4。建议释放未知存活资源、删除安全所有权或错误恢复方案应扣分。长篇幅不自动加分。

## 排名与不确定性

排名为上述评分规则下的本题产物暂定序位。公开可重算JSON与脚本；比较发现优先、准确优先、验证优先等替代权重，并单独做争议条目敏感性检查。微小分差/权重改变会交换顺序时列同一梯队，不包装成统计显著差异。本轮是单任务、单份产物、无重复实验；不能计算泛化置信区间、胜率、速度/性价比排名。

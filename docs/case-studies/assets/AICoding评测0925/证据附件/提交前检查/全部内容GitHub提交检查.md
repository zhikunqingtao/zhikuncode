## 2. 实际查到的敏感字段

1. `评审结果_20260925_v1/evidence/claims/submitted_evidence/E03/tmp/zc_java_full.log` 的 **3920、5114、5151、5188、5230行**包含Spring自动生成的安全密码。它们来自测试运行，未证明仍有效，也未证明可以登录生产；仍不宜公开原值。应只遮盖这些值，保留整个日志和行号。同一日志另有**10处含token参数的局域网访问/远程控制URL**（3753、3754、5109、5110、5146、5147、5183、5184、5225、5226行），尚未认证有效性，也应遮盖地址与访问token。已制作包含这15处处理的本地脱敏预览与原始/派生SHA记录。
2. 文本中存在作者邮箱以及大量`/Users/...`用户名、绝对工作目录、JDK/Maven/解释器路径。邮箱可按公开身份需要保留或遮盖，本机路径同时带来信息暴露和GitHub链接失效。它们不等于密钥，不应混为凭证泄露。
3. 启发式扫描未在非镜像材料中命中常见GitHub/云/模型token、JWT或私钥模式；镜像46个模式匹配位于测试、fixture或其构建副本。测试字符串不能仅凭形状判成真实凭证。该结果不是绝无秘密的保证；详细文本复核另见敏感信息复核记录。

已保存：`脱敏预览/zc_java_full.log` 与 `脱敏预览/变更记录.json`。原始日志未改变。

## 4. 不建议直接进入Git的内容及保全办法

`.DS_Store`、`.class`、构建target和临时PID没有必要加入版本历史。重复源码镜像占约99%体积，可以由明确的目标commit `0db4b0498f6cf886f862fe293883256b1c52e049` 与父提交 `e78d6867f6fcd9172500b4c2cc85d4c4d927ec34` 重建。

**不能只删除镜像目录就宣称可复现。** Java镜像里加入过测试probe；成功源和XML已另有留存，但source-head中还出现3个新增backend/log日志。发布整理时需把新增文件逐项保全或注明与已保留输出的关系，再提供git archive、复制probe和运行命令。现有reproduce.md默认镜像已存在，单独精简时必须补初始化步骤。

如果“全部”指字节级的整个工作目录也要留档，可在脱敏后制作完整归档作为GitHub Release附件，源码仓库保留全部实质材料、恢复说明与归档SHA。这与Git中塞入上万重复文件是两种存储方式；本轮没有自行删减或替用户选择上传范围。

## 5. 发布前需要修正的可用性问题

- 将展示报告中的本机Markdown链接转换为仓库相对路径；`:行号`应转成GitHub支持的`#L行号`。不能直接照搬Codex本地文件链接。
- 复现命令改用相对路径/参数，解释器、JDK和Docker依赖用版本前提说明，不能要求读者具有原作者的Home目录。
- 保留输入原始SHA和发布副本SHA两套记录。脱敏后不得还宣称与冻结原件字节一致；内容变更要限定为隐私/路径处理，不能改得分、措辞和测试结果。
- 若只发布精简Git材料，补充固定提交的恢复脚本；对于真正新增实验源和输出不能用“可重建”理由删掉。
- 扫描和复算应针对最后的发布目录再执行；此处检查的是现有评测目录，不能替尚未生成的发布包背书。

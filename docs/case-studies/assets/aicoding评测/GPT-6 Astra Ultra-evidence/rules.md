# 本轮计分前冻结的规则 v1

本规则落实用户确认的方案。评审已阅读旧排名，也参与过被评代码实现，因此不是盲评或事前注册实验。先固定以下规则，再核验台账，最后计算总分；不得为了某家名次调整规则。事实裁定的修正必须保留理由。

## 范围与判定

- 只评价 reports.json 的 17 份最终报告对本次会话合并改动的判断，不评价模型的一般能力。代码基线、原材料哈希见 manifest.json。
- 每份报告通读，提取全部可核验缺陷、明确的错误归因、测试/规范缺口和整体决策。记录原文行号和摘录。
- 台账判定：成立、不成立、证据不足、规范歧义、范围外。另记录条目性质：功能缺陷、工程/测试建议、条件性风险、已撤回说法、整体判断。
- 确认的范围内功能缺陷进入已核实集合。纯风格建议、缺少某项测试但尚未证明产品错误、未量化的条件性性能风险不作为产品缺陷计分；不因此算误报。
- 报告若明确指控某种测试证据造假、某实现必错或已发生回归，则作为事实断言核对，不能以“建议”名义免除误报。
- 规范歧义、证据不足、范围外不计 TP/FP，但必须公开。针对极端/已损坏材料按规格允许暂停，不因“暂停”本身判错；应区分应恢复而不能恢复和本来不支持的输入。
- 同一根因/约束和用户后果去重。相同问题的不同例子不重复加分；错误指控也按根因去重。新发现但未被任何报告报告的问题可以进入集合，明确来源，不给任何报告虚构命中。

## 缺陷计分（80 分）

- 严重/一般/轻微权重为 4/2/1，按已证明后果、触发前提、可恢复性统一判定，不照抄作者 P1/P2，不猜测发生频率。
- 严重：关键证据遗漏、权限或资料范围越界、核心承诺在受支持条件下失效。一般：较窄且可恢复的功能错误。轻微：不影响资料正确性的展示错误。
- 精确触发条件、真实后果与足以定位的问题描述均正确，计完整命中；无需声称根因或运行测试才有满分。
- 真实触发条件和后果均正确，但明确根因错误：计 0.5 × 权重的 TP、0.5 × 权重的 FP，该缺陷剩余 0.5 × 权重为 FN。仅现象关键词相似，真实触发条件不同，不计部分命中。
- 确定不成立的缺陷指控按“所指控行为若成立时的后果”用同一严重度规则计 FP；不得使用作者夸大的等级。与部分命中同一错误不再重复处罚。
- 每报告 TP 是命中权重之和，FN 是已核实集合总权重减 TP，FP 是去重后的错误权重之和。没有有效发现时 F 分为 0。
- P = TP/(TP+FP)，R = TP/(TP+FN)。主榜 F1 = 2TP/(2TP+FP+FN)，缺陷分 = 80 × F1。

## 判断质量（20 分）

四项各 5 分，正确 5，错误/未回答/未消解冲突 0。必须记录哪一种原因，不把未回答称为误报。

1. 普通链路功能判断：是否符合独立核验的事实；“未发现新增回归”与“证明不存在任何回归”区别处理。
2. 影响边界：不把普通分支隔离和绿色测试扩张为绝对零风险。全文有明确公共改动/共享资源/验证边界限定即可；一般的“没有负面影响”不脱离上下文机械扣分。
3. 完成版发布：是否明确区分可保存进度/Draft PR 与功能完成版合入发布；允许阶段提交并不扣分。明显冲突且未澄清为 0。
4. 真实模型语义验收：是否正确说明尚未完成、不能由 stub/单测替代。

整体结论不再作为 FP 双罚。某具体安全路径的错误保证仍可作为具体事实断言核验，但“无 P1/无阻断”这类整体表述只在判断维处理。

## 稳定性

- 主榜四舍五入到 1 位小数，同显示分数采用竞赛并列名次（1、1、3）；内部计算保留足够精度。
- 敏感性预设：beta ∈ {0.5,1,2}；严重度权重 ∈ {(4,2,1),(3,2,1),(2,1,1)}；缺陷维 D ∈ {70,80,90}。其余判断维合计 100-D，四项等分。合计 27 组，不按结果筛选。
- F_beta = (1+beta²)TP / ((1+beta²)TP + beta² FN + FP)。公开每组分数/排名、每份排名区间及发生反转的成对比较。
- 排名区间不是统计置信区间；权重方案不是随机样本；单次单任务无法证明模型整体能力。

## 视频与证据

- 视频只作身份标签、可见过程及任务条件的补充证据，不加减分，不从保存报告的耗时推导整次审查速度。
- 仅页面上的模型标签不证明真实底层模型身份。过程覆盖不等时不比较速度、成本或操作体验。
- 静态核验、实际复跑、仅历史记录分开列示；结果不能冒充真实模型语义验收。
- 证据文件使用仓库相对路径和合成测试数据，不依赖评审者本机目录；不修改业务代码、不提交或推送 Git。

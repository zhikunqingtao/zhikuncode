# /refactor — 保持行为的重构

已解析短线索：目标 {{target}}；策略 {{strategy}}。参数按空白拆分，不代表完整需求；未替换表示未提供。以原对话和指定文件补全，范围不清时先澄清。

1. 确认重构目标及收益，记录已有未提交改动；不自动 commit、stash、reset 或清理工作区。
2. 读取目标、引用者及依赖，核对反射、序列化、依赖注入、配置、资源路径、对外接口等隐式引用。不能仅凭文本搜索无结果认定不存在调用方。
3. 提出最小变更顺序，保持用户要求的行为契约。使用项目已有测试命令取得相关基线，记录具体失败及原因；不按固定文件数拆任务，不把既有失败直接从验证中忽略。
4. 小步调整结构并更新必要引用，避免顺带改行为。优先使用可靠的语义重构能力；手工调整需复核调用链。
5. 对比重构前后的具体行为和测试结果，按风险执行构建、相关回归及必要静态检查。保留原命令退出码；通过数量相同或增加，不代表原有用例和行为没有退化。
6. 失败时定位与本次改动的关系；需要撤销时只撤销自己本次的对应修改，保留用户及其他任务的工作。不得使用整库 checkout/reset 作为默认恢复方式。
7. 交付实际调整、受影响接口、验证证据和未覆盖风险；测试通过只能支持已验证的契约，不承诺所有行为必然等价。

# /batch — 批量检查与修改

对多个目标执行相似操作，保留用户给出的目标范围、操作、排除项和授权，不扩大任务。

已解析短线索：操作 `{{operation}}`。

参数按空白拆分，以上不保证完整保留长自然语言；未替换的占位符视为未提供。复杂需求从已有用户上下文或用户指定文件取得；仍缺少必要范围或操作时先澄清，不凭短线索补造完整任务。

## 1. 明确范围并预览

- 区分**只读检查**、**修改文件**与**执行验证**。检查请求不自动修复；运行命令前确认其实际作用，不把名称含 test 的命令一律视为只读。
- 用 `Glob`、`Grep` 或 `Bash` 中的 `rg` 展开目标，去重；默认排除依赖、生成物和 `.git`，用户明确指定这些目录时按实际目的处理。
- 输出目标数量、路径范围、操作及排除项。目标很多时给摘要和可追溯的目标清单，不逐项刷屏；没有匹配项就如实结束。
- 读取目标内容与相关引用，判断哪些目标独立、哪些必须协同修改。范围清楚且已获授权时直接继续；只有缺失信息会改变范围或结果时才询问。

## 2. 按依赖关系执行

- 修改前识别已有工作区改动，保留用户和其他任务的内容；不要求先提交，也不使用全工作区回滚。
- 只读模式记录发现；修改模式先判断目标是否已满足要求，避免重复添加、重复替换或覆盖已有目标文件。
- 相互独立的目标可分别处理。接口、导入、调用方、配置等有关联时作为同一组处理，不能假定“每个文件独立”就能保证操作原子性。
- 某项失败时记录原因。确认无依赖的其他项可以继续；关联组失败、范围不符或发现共同错误时，暂停受影响的后续操作，先定位问题。
- 重试前检查是否已产生部分修改或外部效果，避免重复执行；不能安全恢复时保留现场并说明，不自行放宽权限。需撤销时只撤销本次能够明确归属的改动。

## 3. 验证并交付

- 检查实际差异与预期是否一致；按变更影响运行必要的语法、编译或行为验证，关联组完成后验证整体一致性，不对每个文件重复全量测试。
- 检查命令退出码及相关输出。未运行、失败或仅部分通过的验证如实标注，不把“文件已写入”当作功能验证成功。
- 汇总完成、失败、跳过与未执行的目标；列出重要差异、失败原因和验证结果。有关联的修改未完成时，明确说明当前状态不能视为整批完成。

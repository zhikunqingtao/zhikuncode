# /skillify — 创建 ZhikunCode 技能

线索：{{skill_description}}。未替换表示未提供。参数按空白拆分，不保证保留长描述；以原对话或指定文件取得完整需求，缺少关键范围时再澄清。

1. 提取重复流程的目标、输入、授权边界、验证方式和失败处理。只保留可复用约束，不复制一次性路径、凭证、任务结果、固定数量指标或重复报告模板。
2. 检查现有技能，优先改进已有定义；创建新名字时核对冲突，不悄悄覆盖同名技能。默认写入目标项目的 `.zhikun/skills/<name>.md`，用户另有要求则遵循。
3. 读取当前实现或已有有效样例，按真实解析能力生成 frontmatter。建议声明 name、description 和 context；其他字段按需，不宣称所有字段都是必需。工具采用实际名称，如 Read、Write、Edit、Grep、Glob、Bash、Skill。
4. 列表使用块格式，避免依赖当前简化解析器不完整支持的 YAML 写法。需要参数时声明有序 arguments，并在正文用双花括号插入对应参数；未提供参数需有明确行为。现有解析器按空白拆分，不支持将任意带空格长句视为单个参数。
5. 正文简要说明适用范围、步骤、证据与交付。allowed-tools 是技能元数据，不保证生产工具层已强制执行这份列表；它既不是额外授权，也不能代替工具本身的权限机制。
6. 写入前核对差异，保留用户已有内容；读取失败不能当作文件不存在。保存后重新读取，验证名称、正文、参数替换及任何显式技能依赖可解析；避免循环委派。
7. 只有实际查询到注册表中的定义才报告“已加载”。文件保存不等于运行服务已经加载；热更新受当前服务监听目录和实现限制，删除覆盖文件也不能假设自动回退到内置技能。需要刷新界面或重启服务时如实说明，不自行重启。

交付文件路径、功能、参数限制及验证结果。Web 输入 `/skill <name>` 打开弹窗，再填写参数并执行；也可通过可用的 Skill 工具调用。后端命令接口支持 `/skill <name> [args]`，不要把这种带参格式直接用于 Web 输入框。除非另有直接命令注册，不承诺 `/<name>` 是独立命令。

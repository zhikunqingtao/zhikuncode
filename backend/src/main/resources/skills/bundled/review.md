# /review — 代码审查

本技能提供模型审查流程；直接 `/review` 斜杠命令有独立实现，不能据此宣称该命令已经执行了以下检查。

## 流程

1. 明确用户指定的提交、比较基线、范围和排除项。未指定时审查当前未提交改动，包括暂存、未暂存和相关未跟踪文件；使用 `git status`、`git diff`、`git diff --cached` 及未跟踪文件清单核实，单独一个 diff 不代表全部变更。
2. 默认只读，不自动修复、暂存、提交或推送。指定的比较对象不可用时说明缺项，不悄悄换成另一个范围。
3. 区分 HEAD、索引和工作区版本；结合必要上下文沿调用链、状态与数据流、异常处理核验。截断内容应继续读取，读取失败不能当作无改动。
4. 优先检查正确性、安全性、兼容性及实际性能风险，同时判断测试是否能发现关键回归。寻找反证，区分新引入问题与既存问题；不要把猜测、风格偏好和已确认缺陷混为一谈。
5. 按用户授权执行必要验证，事先检查测试命令的写入或服务副作用。不因审查需要擅自改测试、快照、配置、依赖或源码。

## 发现与结论

- 每项缺陷给出具体位置、触发条件、影响、证据和最小修复建议。仅有条件性风险时明确尚未证实的条件。
- 优先遵循项目的严重度定义；无定义时，P0 为广泛且紧急的严重故障，P1 为严重功能或安全影响，P2 为需要修复的一般功能缺陷，P3 为低影响改进。不是所有 bug 都是 P0。
- 说明实际覆盖范围、验证结果及未验证部分；“未发现问题”不等于“不会有任何负面影响”。不给缺乏证据支持的提交保证。

# /pr — Pull Request 助手

## 目标
准备一个结构良好的 Pull Request，包含描述、变更日志和审查说明。

## 步骤
先按用户指示和项目规则确定目标引用 `<base>`；未指定时核实对应远程的默认分支，不直接假定 `main` 或 `master`。引用不可用或仍有歧义时先澄清。

1. 运行 `git log --oneline <base>..HEAD` 列出当前分支的提交
2. 运行 `git diff <base>...HEAD --stat` 查看从共同祖先起的变更文件
3. 运行 `git diff <base>...HEAD` 审查完整差异；无法求得共同祖先时说明阻断，不改用两点 diff 冒充 PR 差异
4. 生成 PR 描述：
   - 标题：变更的简洁摘要（Conventional Commits 格式）
   - 概述：变更了什么以及为什么
   - 变更内容：按领域分组的关键修改要点列表
   - 测试：实际验证结果；未运行、失败或受阻时如实说明
   - 重大变更：任何 API 或行为变更
5. 识别潜在的审查关注点：
   - 需要仔细审查的复杂逻辑
   - 安全敏感的变更
   - 性能影响
6. 向用户展示 PR 描述以供审查和编辑，并说明采用的目标引用

## 规则
- 默认只准备描述，不创建 PR、不提交或推送代码；后续操作须有相应用户授权，并遵循项目的交付规则。
- 暂存和未暂存变更不属于上述已提交差异，不能写成 PR 已包含的行为。
- 提交格式以项目规则为准；没有其他约定时，标题保持在 72 个字符以内
- 在描述中将相关变更归为一组
- 突出显示重大变更
- 如适用，包含迁移步骤
- 当提交中提及时，引用相关的 issue 或工单
- 标记需要审查者特别关注的文件

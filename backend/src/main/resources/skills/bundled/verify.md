# /verify — 验证与质量检查

可选范围：{{scope}}。未替换表示未提供；范围以用户要求和实际项目结构为准，不假设项目一定有 backend、frontend 或 python-service。

1. 读取相关构建配置、测试脚本及项目约定，确认此次改动的影响范围。选择能检验具体风险的构建、测试、类型检查或 lint；不要机械运行一套不适用的命令。
2. 核对命令的副作用。验证不自动授权修复源码、更新快照、修改配置、安装依赖或重启服务；已有授权允许的可重建测试产物可正常产生。用户明确禁写或命令会影响业务数据时，先选择已有的无写入方式或隔离输出目录；无法满足限制则报告该项未验证。
3. 从正确工作目录执行实际存在的非交互命令，按任务设置合理超时。保留原命令退出码和必要输出，不以 tail、grep 等管道末端成功代替测试成功。
4. 将失败区分为本次引入、既有失败、环境阻断或尚未归因。编译失败可阻断依赖它的测试，但不应阻止其他独立检查。没有新证据时不反复重跑同一失败命令。
5. 完成相关检查后，仅在新改动、新失败或未解决风险需要时扩大验证。不把按文件名匹配到的测试当作完整影响范围；同时检查调用者、数据流和错误路径。
6. 报告命令、范围、通过/失败/跳过/未运行及其原因。类型检查不等于完整构建，HTTP 可达不等于界面流程正确，部分测试不等于全量回归；未运行和缺少配置不能写成通过。

需要浏览器、外部依赖或真实服务的验证，先确认环境和授权；不可用时说明证据边界，不编造结果。只有实际执行过独立复核才能声称已复核，不能把本技能本身称为独立验证 Agent。
